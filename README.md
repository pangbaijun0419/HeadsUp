# Heads up

## 初衷与设计思路

Heads up 希望通过一句恰到好处的提醒，让沉浸在手机里的人意识到：自己已经看了很久。用文字带来一点共鸣，让人愿意抬起头、放下手机，把注意力带回生活。

围绕这个初衷，产品有几个设计重点：

- **文案是提醒的核心。** 不只是告诉用户“时间到了”，更希望一句话能被真正看见、打动用户，让习惯性的滑动出现一个停顿。
- **在使用过程中提醒。** 不只在事后展示统计，而是在持续使用时创造一个重新选择的机会。当前原型采用逐步缩短间隔的提醒方式。
- **换一个 App，不等于休息。** 多个所选 App 共同累计使用时间，避免在不同 App 之间切换时重新开始计时；离开达到设定的休息时间后，再开启新一轮。
- **提醒，而不是替用户做决定。** 产品希望通过文字促成主动放下，不以强制封锁为核心。记录保存在本机，是否继续使用，由用户自己决定。

## 当前原型

当前是一个完全本地的 iPhone 原型，通过“快捷指令”个人自动化接收所选 App 的打开、关闭事件，用来验证累计计时、休息重置、提醒节奏与文案体验。

目前支持：

- 首次提醒可设置为 1–120 分钟，之后的提醒间隔逐次减半，最低 10 秒。
- 离开所选 App 后，达到设定的休息时间才重置本轮累计；休息时间可设置为 1–60 分钟。
- 在多个所选 App 之间切换时，继续共同累计使用时间。
- 查看每日与最近七天的聚合使用记录，以及打开、提醒、短休息和异常事件。
- 部分提醒会随机显示“现在放下”行动按钮，按钮文案从一组正向回应中抽取。点击只记录回应，不会打开 Heads up，也不会暂停计时。
- 导出、复制和清空本机使用记录。

当前原型尚未接入 Screen Time／Family Controls，不使用传感器、服务器或远程推送。

这些记录来自快捷指令信号，可能受到信号缺失、重复或延迟的影响。当前统计是所选 App 的共同累计，不是系统级逐 App 精确用量，也不是整部手机的总屏幕时间。

## 正式版方向

后续正式版计划采用苹果原生的“屏幕使用时间”（Screen Time）相关能力，不再依赖手动配置快捷指令，在用户授权后完善使用统计和提醒体验。

原生方案仍需完成相关权限申请、开发与真机验证。具体的数据粒度、后台行为和提醒频率，以系统能力及实际验证结果为准。

技术方案会继续完善，但核心不变：希望用文字触动用户，让每一次提醒都成为抬起头的机会。

以下构建与设置说明针对当前快捷指令原型。

## 构建

```sh
swift test
cmake -S . -B build -G Xcode

export HEADSUP_TEAM_ID="YOUR_APPLE_DEVELOPER_TEAM_ID"

xcodebuild -project build/HeadsUp.xcodeproj -scheme HeadsUp \
    -destination 'platform=iOS,id=<your-device-id>' \
    DEVELOPMENT_TEAM="$HEADSUP_TEAM_ID" \
    PRODUCT_BUNDLE_IDENTIFIER="com.example.headsup.local" \
    -allowProvisioningUpdates build
```

`HEADSUP_TEAM_ID`、设备 ID 和正式 Bundle ID 都只应在本机或私有 CI 变量中提供，不要提交到仓库。

## iPhone 设置教程

以下步骤适用于当前快捷指令原型。请先在 iPhone 上安装 Heads up，并至少打开一次。

### 1. 开启通知

1. 打开 **Heads up → 设置**。
2. 点击“申请通知权限”，在系统提示中选择允许。
3. 如果之前拒绝过，请到 **iPhone 设置 → 通知 → Heads up**，打开“允许通知”，并开启横幅；声音按个人需要选择。
4. 回到 Heads up，点击“安排 10 秒测试提醒”，随后返回主屏幕，检查是否收到通知。

测试通知只用于确认通知是否正常，不能代替下面的快捷指令自动化设置。

### 2. 快捷指令自动化设置

需要在 iPhone 的“快捷指令”App 中建立两条自动化：打开所选 App 时开始累计，离开时暂停累计。

#### 2.1 打开 App 时，开始累计使用

1. 打开“快捷指令”App，进入“自动化”。
2. 点击右上角“＋”；首次使用时，点击新建自动化入口。
3. 找到并选择“App”触发条件。
4. 点击“选取”，勾选希望关注的 App，可以一次选择多个。
5. 只勾选“已打开”，不要同时勾选“已关闭”，运行方式选择“立即运行”。
6. 点击“下一步”，选择新建空白自动化。
7. 搜索 **Heads up** 或 **开始累计使用**，添加 Heads up 提供的“开始累计使用”操作。
8. 点击“完成”保存。

#### 2.2 离开 App 时，暂停累计使用

1. 返回“自动化”，点击“＋”，再创建一条自动化。
2. 触发条件选择“App”，勾选与上一条**完全相同的一组 App**。
3. 只勾选“已关闭”，不要勾选“已打开”，运行方式选择“立即运行”。
4. 点击“下一步”，选择新建空白自动化。
5. 搜索 **Heads up** 或 **暂停累计使用**，添加 Heads up 提供的“暂停累计使用”操作。
6. 点击“完成”保存。

这里的“已关闭”指离开所选 App，不需要每次从后台划掉 App。

两条自动化中的 App 列表需要保持一致。以后增加或移除关注的 App 时，也要同时修改这两条自动化。

不同 iOS 版本的入口名称可能略有差异；如果显示的是“运行前询问”，请关闭它并确认“不询问”。可参考 [Apple 创建个人自动化教程](https://support.apple.com/zh-cn/guide/shortcuts/apdfbdbd7123/ios)及[自动运行说明](https://support.apple.com/zh-cn/guide/shortcuts/apd602971e63/ios)。

### 3. 设置提醒时间并检查

1. 回到 **Heads up → 设置 → 计时规则**。
2. 设置“首次提醒”：这一轮累计使用多久后，收到第一次提醒。
3. 设置“重置累计”：离开所选 App 多久后，下一次使用才开始新一轮计时。
4. 点击“保存计时设置”。
5. 打开一个已选择的 App，使用片刻后返回 Heads up，检查是否出现使用记录。
6. 要测试真实提醒，可以临时将首次提醒设为 1 分钟，保存后进入所选 App 持续使用；测试结束后再改回需要的时间。

如果只是短暂离开，没有达到设定的休息时间，再次进入所选 App 时会继续上一轮累计。重置本轮累计不会清空当天的历史记录。

### 4. 没有记录或没有提醒时

**没有使用记录：**

- 检查两条自动化是否已启用。
- 检查两条自动化选择的 App 是否完全一致。
- 检查“已打开”是否对应“开始累计使用”，“已关闭”是否对应“暂停累计使用”。
- 检查运行方式是否为“立即运行”。
- 检查 Heads up 是否处于暂停状态。

**有使用记录，但没有提醒：**

- 先运行“安排 10 秒测试提醒”，检查通知能否正常出现。
- 检查 iPhone 是否允许 Heads up 发送通知和显示横幅。
- 检查专注模式、通知摘要等设置是否影响通知展示。
- 确认累计使用已达到首次提醒时间，而不是只看当前这一次打开 App 的时间。

## 当前限制

- 快捷指令自动化需要用户手动创建，Heads up 无法代替用户静默完成。
- 当前计时依赖自动化信号，不能保证每次打开、离开和切换都被完整记录。
- 提醒采用有限批次预排，不能保证在后台无限持续地按 10 秒间隔提醒。
- 系统是否展示横幅、播放声音及何时送达，受通知权限和系统状态影响；记录中的“提醒应触发”不等于通知已经送达或被阅读。
- 点击提醒中的回应按钮，只能说明用户进行了回应，不能证明已经放下手机或完成休息。
